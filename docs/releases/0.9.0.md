# RhapsodIA 0.9.0

Date: 2026-10-14. Complete source distribution; no published tag or remote deployment is claimed.
Previous release: **0.8.0**.

## Summary

RhapsodIA 0.9.0 distributes **56 Agent Skills and seven canonical native agent profiles**, up from 53 skills and seven agents in 0.8.0. The three new skills are **Reverse Engineering**, **Deep Research Suite**, and **Premortem Analysis**. Four existing skill packages evolve: **Skill Token Efficient**, **Skill Booster**, **Skill Creator Juiced**, and **Skill Benchmark**. The runtime-harness and operational-context behavior, domain ownership and canonical agent sources remain unchanged.

## Added

- **Reverse Engineering 0.1.0:** six bounded modes (Discover, Investigate, Characterize, Reconstruct, Verify, Diagnose); offline static inventory across supported source/binary/interface inputs; evidence/provenance graph, behavioral probes, state/contract comparison and optional trusted runtime verification. It does not grant execution or guarantee equivalence. Roslyn/.NET, Ghidra, browser and other external adapters are optional and authorization-gated.
- **Deep Research Suite 0.2.0:** single portable workflow for planning, researching, refining fields/items, safe resume, report generation, and standalone source-aware web investigation. Results distinguish schema validity from research readiness and include verifiable source/claim links, explicit unresolved evidence and reproducibility markers.
- **Premortem Analysis 0.1.0:** prospective, explicitly hypothetical plan-failure analysis in quick, standard and governed modes, with causal mechanisms, counterevidence, controllability, prevention, detection and verification. It is advisory, not an incident postmortem or authorization to change a plan. Python standard-library validators and reproducible packaging are optional.
- **New-skill version identity:** Reverse Engineering and Premortem Analysis both have an explicit initial `VERSION` of `0.1.0` and matching `CHANGELOG.md` entries, without inventing earlier release history.
- **0.9.0 source-manifest validator:** deterministic source hashing, portable path-collision checks and a generated, CI-checkable source inventory.

## Changed

- **Skill Token Efficient 0.1.1:** primary owner of format selection and token-efficiency evidence through `skill-opt.token-efficiency` v1, with guarded eligibility rather than declaring universal savings for JSON, YAML, Markdown, TOON or other formats.
- **Skill Booster 0.2.0:** optional import of the Golden Source for format advice, staged optimization and comparison; retains independent validation/promotion authority and mandatory new/optimized skill version records.
- **Skill Creator Juiced 0.2.0:** optional read-only owner-contract consumption during creation/redesign; preserves creation authority, acceptance gates and required version history.
- **Skill Benchmark 0.1.0:** optional token-efficiency inputs for separately evidenced, identity-bound comparison. It does not inherit acceptance authority from the provider or invent benchmark gains.
- **Package/CI version synchronization:** `marketplace/catalog.json`, four host plugin families, source and agent manifests, release validators and both release workflows now identify 0.9.0. An inherited 0.7.0 pin in the primary release workflow is corrected.
- **Test collection:** the primary release workflow runs pytest-style tests through pytest rather than executing their modules as scripts without collecting test functions. Both CI workflows now include Premortem Analysis tests and portable validation. Pytest is a pinned **CI-only development dependency**; it is not required by the installed skill runtime.
- **Distribution hygiene:** removed a byte-identical nested ZIP of Deep Research Suite from staging; the release still contains the complete skill source directory and its tests.

## Compatibility and operator actions

1. Replace the full source distribution; do not install only some 0.9.0 catalog components while retaining older generated host manifests.
2. Preserve user customizations outside managed host blocks. Native host configuration remains opt-in. No new background agent service, database, provider token, or third-party orchestrator is required.
3. Existing Deep Research Suite workspaces may need **targeted revalidation**: newly strict required-field defaults, source/claim support, resume stamps and report completeness can change whether old results are eligible for reuse. No source material or canonical results are automatically migrated or overwritten.
4. New or optimized skill packages require root SemVer `VERSION` and a matching current `CHANGELOG.md`. Unchanged legacy packages are not bulk-versioned.
5. On rollback to 0.8.0, preserve Nomia/Mago/Magia/Verifier canonical records and restore the full old distribution; invalidate incompatible disposable derived state rather than rewriting domain data.

## Known issues and limitations

- Complete root integration and combined pytest suites did not finish within the available local execution window. Focused critical suites and validators passed, but this is not a full-repository green-test claim.
- Deep Research Suite, Skill Token Efficient, and Skill Benchmark retain independent activation-scenario/evaluator formats incompatible with the Creator Juiced generic activation-suite schema. Their frozen scenario inputs were not modified solely to satisfy a different evaluator. Passing their own gates does not mean every generic evaluator format was accepted.
- The **supplied 0.8.0 main** has a stale historical source manifest (seven file-hash mismatches plus one omitted eligible file, `.gitattributes`). That historical document was intentionally preserved. The new 0.9.0 inventory is generated and checked from the delivered candidate's bytes.
- Local fixture tests and structural portability checks are not native Windows/macOS or real GitHub Actions/IDE/model execution results. There is no claimed paid-token reduction, general behavioral equivalence, live browser/toolchain conformance, hosted deployment, production rollout or external security certification.
- Optional external tools and trusted programs require explicit origin/environment authorization. Behavioral probes are not an operating-system sandbox, and hashes are identity checks rather than signatures or trust in a malicious same-user writer.

## Rollback and release integrity

Stop writers, restore the entire original 0.8.0 distribution identified above, and revalidate/install host adapters as needed. Keep domain records and evaluator evidence outside disposable runtime caches. Compare the external ZIP SHA-256 receipt against the downloaded archive before distributing. Do not treat prior manifests or cached pointers as proof of a new gate result.
