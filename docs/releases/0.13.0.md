# RhapsodIA 0.13.0 — portable expertise discovery

## Release source and preserved improvements

The authoritative baseline is the user-supplied `rhapsodia-main (7)(1).zip` (SHA-256 `28ae8aa5a64d9c79f808f5cbd691412335af79cb821101e751f89d70c75ddf51`), **not** the earlier 0.12.1 archive. Preserved 0.12.0 baseline capabilities include the newer metamorphic-evidence validators and references from Skill Benchmark, Reproducibility Engineer and Skill Prompt/Activation Review; targeted updates in Decision Engine, Reverse Engineering, Runtime Harness and Operational Context; and all original domain/agent lifecycle controls. No existing Skill files were replaced with older versions.

## Design choice

- Create **one new Skill** `capability-discovery` v0.1.0 instead of an additional autonomous agent. It helps locate expertise but owns no task, workspace, lifecycle, approvals or execution.
- Move all runtime-needed capability routing guidance, CLI and tests inside the Skill package. There is no runtime dependency on `docs/agents/CAPABILITY-DISCOVERY.md` or an external source-tree `scripts/capability_directory.py`.
- Add brief instructions to the first 100 physical lines of each of the eight existing agents without removing their session, graph, ownership, authority, stop or output requirements.
- Use host-native Skill/agent discovery first; the local CLI provides only an inspected source-pinned shortlist. Check source identity, actual host availability, semantic non-use boundaries, and permissions before choosing.
- Preserve the `agent-system-contract/v4`, `handoff/v1`, ecosystem handoff v3, native Supervisor allowlist, independent Verifier and one canonical writer. The contract's new `discovery_skill` section is additive and authority-neutral.

## Installation / portability

- Plugin installations that support `skills/` can discover this complete self-contained Skill in the existing published component. No mandatory project `docs/` directory is needed.
- The standalone `.github/agents` installer copies the eight profiles and the Skill to `.github/skills/capability-discovery/` by default. `--agents-only` makes this addition optional, while keeping host-native discovery and the original domain/runtime/graph Skill prerequisites.
- Custom paths outside the current workspace can be passed to the local CLI using explicit approved `--skill-root`/`--agent-root`; the CLI never infers complete host inventory.
- Measured activation across Cursor, Claude, Copilot and Codex is **not established** by structural tests; execute host-specific integration checks for any claim about that behavior.

## Research and traceability

The Skill packages its own [`research basis`](../../skills/capability-discovery/references/research-basis.md) and operational [`routing`](../../skills/capability-discovery/references/routing.md). Human-team transactive-memory evidence informs the design analogy but does not prove AI-agent improvement. Sources include Wegner (1987), Liang et al. (1995), and Lewis (2003), with DOI links in the Skill. Findings R-1 through R-6 are tied to bounded changes and tests in the research basis. Existing-corpus findings are not a fabricated model benchmark.

## Validation and limitations

Run the agent validator, Skill's own test suite, installer integration tests (including repair/`--agents-only`/symlink guards), source-preservation hash comparison, release versions/manifests and deterministic twice-built full ZIP. Structural tests and manifest integrity do not prove agent routing accuracy or cross-host execution. If any mandatory validation cannot run, report it as `not-run` rather than inventing a pass.
