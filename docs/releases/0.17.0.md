# RhapsodIA 0.17.0 — Decision interviewing and evidence-centered engineering skills

## Overview

RhapsodIA 0.17.0 adds **seven** independently versioned Agent Skills, increasing the catalog from **69 to 76** and retaining all eight native agent profiles. The new packages are adaptations of Matt Pocock's MIT-licensed Skills, sourced from the owned fork pinned at `4ae2317ddb22b046e26455e4f9c9b3aaaf62212d`. This document describes prepared source changes, not a published release, successful CI or host installation.

## New Skills

| Skill | Package version | Role |
|---|---|---|
| [Grilling](../../skills/grilling/SKILL.md) | 0.1.1 | Bounded decision-frontier interviews with explicit recommended answers and evidence/fact distinction |

## Composition and boundaries

- `grill-me` routes to `grilling`; `grill-with-docs` composes `grilling` + `domain-modeling`. Named skill invocation is preferred, but hosts without a skill-dispatch API can reuse readable instructions or perform the same bounded semantics inline. These paths disclose what actually ran.
- `wayfinder` makes **decision** maps, not delivery roadmaps. Nomia keeps business priority/status/ownership. Mago keeps canonical technical planning/specifications/ADRs. Magia keeps execution, tests and execution evidence.
- `retro` may propose sanitized reusable lessons; existing memory/policy owners decide whether they are stored or promoted.
- `code-review` complements the existing `audit-spec-implementation` coordinator's optional Spec-axis specialist. A standards review is not a conformance-verification oracle or approval.
- Fresh-context subagents are optional host capabilities. Sequential fallback is explicit; never claim independent agent review or executed validation without evidence.

## OpenAI and cross-host portability hardening

All seven independently versioned skill packages now include **`assets/icon.svg`**, referenced by both **`icon_small`** and **`icon_large`** in their optional `agents/openai.yaml` adapters. The metadata additionally supplies a six-digit `brand_color`, a skill-aware `default_prompt`, supported `CHAT`/`CODEX` policy products and intentional implicit-invocation flags. These are ChatGPT/Codex UI settings; the canonical `SKILL.md` files remain host-neutral.

The structural support matrix is:

| Host profile | Contract | Capability limitation |
|---|---|---|
| Agent Skills portable core | Common `SKILL.md`, local references and package identity | Does not guarantee interactive model behavior |
| ChatGPT / OpenAI | Optional icon-bearing `agents/openai.yaml` with discoverable SVG assets | Actual installation, rendering and runtime activation still require host verification |
| Codex | Same portable core and optional OpenAI adapter | Tool availability and UI rendering vary by product |
| Claude Code | Portable core and read-only/inline fallback; no Claude-private directives | Native skill-to-skill invocation is not assumed |
| GitHub Copilot | Portable core and capability-based tools | Tracker/auth access must be obtained and authorized separately |
| Cursor | Portable core and capability-based tools | No Cursor-only metadata or mandatory installation path |

`grill-me` remains an explicit alias of Grilling; `grill-with-docs` still combines Grilling and Domain Modeling. When a host cannot invoke another skill, these packages use same-conversation instruction reuse or a documented inline fallback, rather than failing or pretending to delegate. Wayfinder also supports an inline interview and returns a Markdown map when persistent writes are unavailable.

**Validation:** CI runs the Skill Booster structural validator and six-profile portability validator, an Agent Skills package validator, SVG/XML+metadata checks, and archive-content assertions on all seven skills. This is **structural and deterministic host-compatibility evidence**, not a claim of real ChatGPT/Claude/Cursor UI installation or cross-model behavioral equivalence. Full host activation must be verified in each installed client.
