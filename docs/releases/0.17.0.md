# RhapsodIA 0.17.0 — Decision interviewing and evidence-centered engineering skills

## Overview

RhapsodIA 0.17.0 adds **seven** independently versioned Agent Skills, increasing the catalog from **69 to 76** and retaining all eight native agent profiles. The new packages are adaptations of Matt Pocock's MIT-licensed Skills, sourced from the owned fork pinned at `4ae2317ddb22b046e26455e4f9c9b3aaaf62212d`. This document describes prepared source changes, not a published release, successful CI or host installation.

## New Skills

| Skill | Package version | Role |
|---|---|---|
| [Grilling](../../skills/grilling/SKILL.md) | 0.1.0 | Bounded decision-frontier interviews with explicit recommended answers and evidence/fact distinction |
| [Grill Me](../../skills/grill-me/SKILL.md) | 0.1.0 | Explicit alias invoking Grilling; no duplicated interview method |
| [Grill with Docs](../../skills/grill-with-docs/SKILL.md) | 0.1.0 | Compose Grilling and Domain Modeling to draft approved decisions and documentation |
| [Domain Modeling](../../skills/domain-modeling/SKILL.md) | 0.1.0 | Resolve domain vocabulary, bounded-context differences, concrete scenarios and candidate ADRs |
| [Wayfinder](../../skills/wayfinder/SKILL.md) | 0.1.0 | Map multi-session decisions, blockers, unresolved fog and source-linked outcomes |
| [Retro](../../skills/retro/SKILL.md) | 0.1.0 | Recommend environment, verification and workflow improvements from observed sessions |
| [Code Review](../../skills/code-review/SKILL.md) | 0.1.0 | Independently report Standards and Spec review axes for frozen Git diffs |

## Composition and boundaries

- `grill-me` routes to `grilling`; `grill-with-docs` composes `grilling` + `domain-modeling`. Missing underlying skills are reported, not silently replaced.
- `wayfinder` makes **decision** maps, not delivery roadmaps. Nomia keeps business priority/status/ownership. Mago keeps canonical technical planning/specifications/ADRs. Magia keeps execution, tests and execution evidence.
- `retro` may propose sanitized reusable lessons; existing memory/policy owners decide whether they are stored or promoted.
- `code-review` complements the existing `audit-spec-implementation` coordinator's optional Spec-axis specialist. A standards review is not a conformance-verification oracle or approval.
- Fresh-context subagents are optional host capabilities. Sequential fallback is explicit; never claim independent agent review or executed validation without evidence.

## Release, validation and delivery

Expected source changes include the canonical `skills/` folders, `marketplace/catalog.json`, generated manifests for GitHub Copilot, Cursor, Claude and Codex/ChatGPT, `MANIFEST.json`, versioned source hash inventory, release notes/changelog, version assertions and CI checks.

Recommended gate sequence (actual execution and results must be reported separately):

```sh
python -I -S -B -m unittest discover -s tests -p 'test_mattpocock_adaptations.py' -v
python -I -S -B scripts/validate_skill_descriptions.py
python -I -S -B -m unittest tests.test_release_versions -v
python -B scripts/prepare_release.py --check
python -B scripts/validate_release_source_manifest.py --version 0.17.0 --check
python scripts/build_release_archive.py --version 0.17.0 --output dist/rhapsodia-0.17.0.zip
```

The complete GitHub Actions pipeline and host-platform matrix must pass on the PR revision before any release-ready claim. Release creation, tagging and merging are out of scope.
