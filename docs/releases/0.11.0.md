This same-release revision keeps **0.11.0**, independent skill versions, existing CLI/storage
schemas and domain permissions unchanged. All eight profiles now state why Harness and Graph
are required within their first 100 lines: avoid repeated discovery and retain useful structural
and operational learning across agents/sessions in the approved workspace.

Rules distinguish relevant retrieval from ritual queries, selective learning from record quotas,
and source-derived indexes from operational knowledge that may not be reconstructible. Reuse
the current lookup for unchanged questions/evidence; investigate unresolved scope, update only
meaningful findings and report `no-new-reusable-knowledge` with a reason when none qualifies.
Necessary source inspection, current acceptance and independent proof are never traded for
fewer tokens. No hidden hook, dependency, external service or new orchestration is introduced.

Owning skill roots, managed native-host guidance, the direct learning guide, additive mutation
guards and planned agent scenarios preserve the same purpose. Instructions/guards do not prove
universal host enforcement or model comprehension. Research is rationale, not borrowed metrics.

## Required sessions for every agent

All eight agent profiles now require Runtime Harness and Local Graph Engine before repository
search, domain work, project commands or delegation. Missing state is initialized; valid state
is reused. Missing capabilities, permissions, helpers or valid state block the affected work.
Only an explicit user request disables harness and/or graph independently for that request.
Disabled components are not accessed and no persistent global opt-out is installed.

The paired bootstrap is `runtime-harness/scripts/agent_session.py`; the source repository
also exposes `scripts/session.py`. A successful receipt identifies the real private runtime
pointer and SQLite graph plus exact local helper argument arrays. The standalone runtime
registry remains graph-independent for existing consumers outside these agent profiles.

## Graph-first discovery and reusable troubleshooting

The new `local-graph-engine/scripts/workspace_memory.py` supports start/status, bounded lookup,
source pinning, revision-controlled learning, reconciliation and runtime projection import.
The source repository offers `scripts/memory.py` as a convenience. Knowledge stays in
`.rhapsodia/graph/workspace.sqlite3`, outside canonical product files and version control.

Fresh graph references lead to exact source reads rather than another broad keyword search.
Missing, stale, insufficient or truncated results require bounded source investigation and
publication of useful new findings. Source SHA-256 pins, stable keys and expected revisions
prevent silent replacement and blind revalidation. The graph never proves source correctness
or repository-wide absence.

Environment recipes distinguish observed success, documentation, hypothesis, failed attempts
and authentication requirements. They preserve sanitized symptoms, diagnosis, resolution,
verification, applicability and environment-variable names, never credential values or raw
logs. Environment drift and expiry invalidate reuse. Renewing a stale recipe requires explicit
current-revision publication after re-verification; identical fresh records remain no-ops.
No recipe is executed automatically, and no helper installs tools, logs in or bypasses policy.

Default reconciliation invalidates changed or missing references. Complete-scope pruning is
explicit and restricted to confirmed missing single-source records. Sparse checkouts, branch
switches, failed searches and inaccessible files are not deletion proof. Other source evidence
and revision history survive.

## Direct Adhoc agent

`Rhapsodia Adhoc` is a second public entry point for one direct authorized task. It selects
relevant installed skills and executes them inline, with no subagent tool, worker graph or
orchestration loop. Runtime and graph remain mandatory unless explicitly disabled by the user.
An existing governed lifecycle, selected skill boundary or independent proof requirement
cannot be bypassed by choosing Adhoc.

Supervisor retains governed coordination. Analyst and Supervisor have no direct edit tool;
their newly required execute capability is limited by contract to reviewed private-memory
helpers. Host-native approval and sandbox controls remain necessary because a coarse execute
tool is not a command allowlist. Canonical Nomia/Mago/Magia/Verifier ownership is preserved.
Rhapsodia Workspace remains optional derived artifact presentation, not session or memory setup.

## Reverse Engineering 0.2.0 - Dynamic Investigation & Behavioral Auditing

The RhapsodIA **0.11.0** distribution includes the independently versioned
Reverse Engineering + Behavioral Reconstruction **0.2.0**. This release expands the skill
from static analysis and finite behavioral verification into broader application investigation
while preserving its existing modes, contracts and trust boundaries. See the
[skill README](../../skills/reverse-engineering/README.md) and
[skill changelog](../../skills/reverse-engineering/CHANGELOG.md).

### Highlights

- **Dynamic web investigation:** `web_investigator.py` is the sole supported Playwright
  entrypoint. It supports bounded navigation and interactions, including clicks, form input,
  keyboard actions, hover, drag-and-drop, selection and scrolling. It records DOM, network and
  console metadata, complete selected-element SHA-256 hashes, explicit text capture, optional
  screenshots, viewport measurements, local timings and bounded same-origin exploration.
- **Policy-driven web auditing:** `web_audit.py` evaluates recorded UI and HTTP evidence against
  independently defined functional, HTTP, timing, layout and security-header expectations,
  including typed JSON Pointer assertions and viewport-overflow checks. Outcomes are explicitly
  `pass`, `fail` or `incomplete`; missing evidence is not treated as success.
- **Passive security analysis:** `source_marker_scan.py` performs bounded source inspection and
  returns redacted credential-marker findings. It does not validate or attempt to use credentials.
- **Evidence correlation:** `correlate_web_evidence.py` associates browser requests with candidate
  API routes and persists observations in the SQLite evidence graph; inferred relationships
  remain labeled as inferred, not verified backend behavior.
- **Offline fixture support:** approved local HTML fixtures enable browser tests where HTTP
  navigation is restricted. Fixture results are clearly distinguished from actual HTTP evidence.
- The six existing modes, 13 MCP tools, static analyzers, Behavioral Lab V1/V2 contracts and
  differential verification remain unchanged.

### Breaking change and migration

The standalone `scripts/browser_capture.py` CLI and its Python import surface were removed.
From the installed skill root, migrate captures to:

```sh
python3 scripts/web_investigator.py capture \
  --origin http://127.0.0.1:8080 \
  --actions approved-actions.json \
  --execute-authorized \
  --mutations-approved \
  -o trace.json
```

Interactive actions require explicit mutation approval as well as authorization for a trusted
target; these flags do not grant consent or isolate execution. Trace outputs now use
`mode: web-investigation` with `steps` and `events`, replacing
`mode: authorized-browser-capture` with `observations`. External trace consumers must migrate
their field mappings; no compatibility alias is provided. Python consumers should import
`checked_actions` and `inspect_browser` from `web_investigator`. Existing Behavioral Lab
V1/V2 records, MCP tool names and static-analysis CLI commands are unchanged.

### Portability, validation and limits

The portable core remains Python 3.10+ and standard-library-only. Playwright, Chromium and
external analyzers are optional and are not installed or downloaded automatically. Capability
detection and trusted offline fixtures preserve a useful path when browser HTTP access is
unavailable. Structural package validation covers OpenAI, Codex, Claude, GitHub Copilot, Cursor
and the portable-core profile; the primary `SKILL.md` control plane remains within 99 physical
lines. The skill's `VERSION` and `CHANGELOG.md` preserve its independent SemVer history.

The package's recorded validation includes 173 passing tests in the original baseline, 182 in
the first expanded version (0.1.0) and 183 in the consolidated version (0.2.0). Playwright and
Chromium were exercised with trusted offline HTML fixtures; web-audit and evidence-graph
integration were tested with synthetic examples. Migration guards cover permission and path
checks, selected-text hashing, optional screenshots and blocked-overwrite behavior. Existing
regression scenarios were preserved.

Browser HTTP navigation across hosts was not validated in the restricted ChatGPT sandbox.
Offline fixtures do not establish remote or backend behavior, and browser request interception
is not OS-level network isolation. Performance observations do not replace Core Web Vitals or
Lighthouse; bounded security checks do not replace full SAST, DAST, penetration testing or
authorization audits. Structural package compatibility does not prove runtime equivalence across
all supported hosts.
