# RhapsodIA 0.8.0

Date: 2026-10-08. Full source distribution; no published tag or remote deployment is claimed.
Previous release: 0.7.0. The supplied baseline archive SHA-256 is
`47c340cfacebc47b1e91f820ef775112264bf1a6fbc0dc8a09f7ee12602e13f2`.

## Summary

The catalog now contains **53 skills and seven native agent profiles**. This release
adds **Operational Context 1.0.0** and updates **Runtime Harness 1.1.0 to 1.2.0**.
It reuses verified observations and work references while keeping canonical records,
execution authority, fresh validation and independent verification with their owners.
No third-party orchestrator, daemon, network service, provider SDK or database is required.

## Added

- **Task context packs:** ordered required/optional file references, bounded UTF-8 payloads,
  whole-file SHA pins, explicit omissions, no mandatory-context truncation, optional immutable
  storage and live verification before reuse. Inline content requires explicit approval.
- **Progressive command discovery:** 22 JSON commands with a small inventory and per-command
  request schemas; agents need not load the complete command catalog or every example.
- **Output cards and stable prefixes:** reference-first log cards with approved bounded excerpts;
  static-prefix/dynamic-tail separation without claiming a provider cache hit.
- **Artifact/evidence index:** scope-bound disposable pointers, receipt/producer consistency,
  expiry and live candidate-file checks. A current pointer is not a current gate verdict.
- **Conservative action-result lookup:** exact action/input/config/toolchain/environment/policy
  keys and live receipt/output checks for declared hermetic deterministic work. No command
  execution or output restoration. Test, fresh-proof and independent-proof requests bypass it.
- **Usage and comparisons:** normalize supported reported provider counters without double
  counting; missing metrics remain null. Content-free events and paired comparisons reject
  identity, cache-state and quality confounds; descriptive samples are not population proof.
- **Efficiency policy:** single/serial-first suggestions; cost-justified same-owner read-only
  fan-out; exact-reference/text-first retrieval with optional graph use for repeated relations.
- **Observed capabilities:** `capability://` records bind a current tool identity to a matching
  existing receipt. Publication and resolution do not run a probe or grant permission.
- **Typed discovery history:** bounded missing/denied/incompatible/transient/broken/stale
  observations and strategy statistics, invalidated by TTL, scope, target identity and PATH.
- **Delta transport:** exact acknowledged parent, bounded declared chain depth, immutable
  reconstructed handoff identity and full fallback. Domain/agent-control handoffs are unchanged.
- **MCP 2026-07-28 stdio profile:** per-request metadata, `server/discover`, complete results
  and private catalog caching hints. Legacy 2025-11-25 and 2025-06-18 sessions remain supported.
- **Explicit exchange and leases:** path-free selected pointer export, allowlisted quarantined
  import, cooperative holder/nonce/generation/expiry checks; no automatic trust or execution.
- **Graph projection:** data-only observed capability/reference relationships; Local Graph v3
  stays optional and its producer/viewer packages are unchanged.

## Changed

All seven agents use shorter runtime guidance and optional capability-based discovery of
operational helpers. The Supervisor retains ownership routing, one canonical writer and
required verification while choosing delegation from actual independence and known costs.
Native manifests and release metadata use 0.8.0. Runtime integration adds the disposable
cache directory to `.gitignore` only during explicit host configuration.

## Required actions

Replace the complete distribution and refresh authorized runtime state when its installation
identity changes. Review customized host blocks before opting into configuration; do not
change canonical domain records. No extra provider credential or service is required.

## Upgrade and compatibility

Read [the migration guide](../runtime/MIGRATION-0.8.0.md). No mandatory domain-data migration
or new permission is introduced. Existing runtime snapshot/handoff APIs remain valid;
old runtimes should not consume new snapshots after rollback. Refresh or rebuild only
runtime-derived state, never Nomia/Mago/Magia artifacts. Host configuration remains opt-in.

## Known issues

No paid-token reduction, end-to-end agent speedup, native IDE routing accuracy or full MCP
conformance certification is claimed. Linux/Python/stdio behavior is tested locally;
Windows/macOS and real host/model runs remain unexecuted here. The CI matrix is configured,
not an executed platform result. Byte reductions are not token reductions.

Caches are optional, finite and disposable. On corrupt, stale or unavailable evidence,
recover through canonical sources; do not retry unsafe work or lower a gate. Action input
completeness/hermeticity are explicit caller attestations, not sandbox-enforced guarantees.
Leases coordinate consenting callers and exact logical keys, not arbitrary overlapping
paths or native applications. Local hashes do not authenticate a malicious same-user writer.
Federated pointers never become automatic local action/evidence hits. Native prompt cache
configuration and model selection remain host-controlled.

## Rollback and integrity

Stop current writers, restore the previous full source/agent distribution, and rebuild
incompatible disposable runtime/cache data if needed. Preserve user policy outside managed
blocks and every canonical domain artifact. The external archive receipt identifies the
exact ZIP SHA-256; no circular self-hash is embedded in this document.
