# RhapsodIA 0.16.0 — Spec conformance auditing and Git branch reconciliation

## Overview

RhapsodIA 0.16.0 adds **seven independently activatable Agent Skills**, bringing the catalog from **62 to 69 Skills**, while retaining all **eight native agent profiles**. Six skills support read-only, evidence-backed spec conformance audits. The seventh adds guarded branch-content reconciliation for diverged Git histories without merge commits.

This is a source release preparation, not a publication, tag or automatic merge.

The coordinator includes a dispatch registry, evidence/report/handoff references, activation scenarios, standard-library Python scripts, and report-validation unit tests. Each stage adapter includes its version, changelog and activation fixtures. Every new Skill has portable host-discovery metadata and package identity notes.

## Specialist composition and fallback

The coordinator uses the existing RhapsodIA `reverse-engineering`, `causal-flow-comprehension` and `test-oracle-engineering` Skills when they are available, applicable and actually callable. It does **not** duplicate those implementations. `sdd-reviewer` and `code-review` remain optional external specialists; they are not shipped by 0.16.0. Each relevant audit stage has an independent local fallback and records whether the route was invoked or merely proposed.

The routing registry and helper select **plans**; they never invoke external skills by themselves. Skill installation, planned routing, source matches and green CI are not proof that an audit stage or a real behavioral test ran.

## Git branch reconciliation

The new [Branch Reconciliation](../../skills/branch-reconciliation/SKILL.md) package uses Git 2.38+ and Python 3.10+ for two guarded modes: `plan` computes the unique common ancestor, full source/destination tree inventories and a candidate without updating either branch; `apply --confirm` revalidates the frozen plan and creates a single-parent destination commit through a compare-and-swap local ref update. Concurrently changed files require explicit semantic review; Git conflicts require a complete reviewed resolution manifest. The helper never fetches, publishes, force-pushes, or runs project commands on its own. Remote publication, CI and actual behavior validation are separate authorized actions.

The workflow is exercised using synthetic Git histories and does not depend on a particular application repository. See [package record](../../skills/branch-reconciliation/SOURCE.md), [manual resolutions](../../skills/branch-reconciliation/references/manual-resolution.md) and [validation and remote delivery](../../skills/branch-reconciliation/references/validation-and-remote.md).

## Usage and verification

Run standard-library coordinator tests and catalog checks from the repository root:

```sh
python -I -S -B -m unittest discover -s skills/audit-spec-implementation/tests -p 'test_*.py' -v
python -I -S -B -m unittest discover -s skills/branch-reconciliation/tests -p 'test_*.py' -v
python -I -S -B -m unittest discover -s tests -p test_branch_reconciliation_distribution.py -v
python -I -S -B -m unittest discover -s tests -p test_spec_conformance_distribution.py -v
python -I -S -B scripts/validate_skill_descriptions.py
python -B scripts/prepare_release.py --check
python -B scripts/validate_release_source_manifest.py --version 0.16.0 --check
```

The optional planner accepts a JSON request containing frozen `base_sha` and `head_sha`, available skill names, selected stages, and risk factors:

```sh
python -I -S -B skills/audit-spec-implementation/scripts/plan_audit.py request.json
```

A report may be structurally checked with `scripts/validate_report.py`; individual handoffs can be checked with `scripts/validate_stage_receipt.py`. These checks do not prove the claims in the artifacts. Actual audit conclusions require original sources, code-path evidence and adequate execution evidence.

## Compatibility, authority and limitations

- **Additive change:** no existing Skill or agent role is replaced; semantic contracts are independently versioned and unchanged.
- **Read-only audit authority:** spec audits do not edit source, issues, PRs or release state, and do not execute untrusted target code without separate authorization and safe isolation.
- **Guarded Git authority:** branch reconciliation planning never moves refs; local application requires explicit authorization, a fresh source/target baseline and recorded concurrent-edit review. Remote push is deliberately outside its helper.
- **Package identities:** the six conformance Skills retain their independently tracked versions and validation contracts. Branch Reconciliation implements a generic Git tree-integration pattern, with tests based on synthetic repositories. No external upstream Git commit is asserted for these packages.
- **Verification scope:** source-manifest, portable package and unit-test checks do not establish native host activation, full PR conformance or test results for an audited target.
- **Rollback:** use the previous immutable 0.15.0 source tag/archive. Independently installed Skills may need host-specific removal.
