# RhapsodIA 0.14.0 — bounded software improvement

## Release scope

This distribution builds on RhapsodIA 0.13.0, with **59 Agent Skills** and the existing **eight native agent profiles**. The only newly integrated Skill is **Software Improvement Loop v0.1.0**. Other Skills retain their independent SemVer identities.

## Software Improvement Loop

- **Modes:** performance, feature improvement, test hardening, and behavior-preserving simplification.
- **Frozen acceptance:** capture a baseline, success criteria, evaluator identity, representative tests, and guardrails before changing candidates.
- **Recoverable changes:** isolate work, protect existing contributions, and require authorization before destructive operations or changes to public contracts.
- **Bounded attempts:** default to three iterations and one writer; stop when safety or evidence gates are invalid.
- **Measured decision:** report keep, revert, inconclusive, or blocked with supporting tests and comparable measurements; never weaken tests to manufacture success.
- **Portable package:** contains the self-contained control plane, references, examples, activation scenarios, report templates, and standard-library-only metric comparator with regression tests.

The Skill is located in [`skills/software-improvement-loop/`](../../skills/software-improvement-loop/SKILL.md). This places it in established host-plugin discovery and release archive paths rather than at the repository root. PandaCode support is optional; the Skill has no mandatory PandaCode runtime dependency or new agent permissions.

## Release packaging and CI

- Update marketplace and host plugin versions, agent manifest, README, version inventories, source manifest, archive naming, and version tests to `0.14.0`.
- Add the new Skill to archive completeness assertions and run its tests in the full release and cross-platform portability workflows.
- Run the full release workflow on pull requests, in addition to its existing push and manual events.
- Preserve the 0.13.0 release records unchanged for historical auditability.

## Version boundaries

`0.14.0` is the **distribution** identity. The new Skill is `0.1.0`. Internal semantic contract versions, the eight native agent profiles, required Runtime Harness/Local Graph sessions, and Nomia/Mago/Magia ownership remain unchanged.

## Validation commands

```sh
python -I -S -B -m unittest discover -s skills/software-improvement-loop/scripts/tests -p 'test_*.py' -v
python -B scripts/prepare_release.py --check
python -S -B -m unittest tests.test_release_versions -v
python -B scripts/validate_release_source_manifest.py --version 0.14.0 --check
python scripts/build_release_archive.py --version 0.14.0 --output dist/a/rhapsodia-0.14.0.zip
```

The workflows also run retained regression suites, repeat archive builds, and verify ZIP integrity. CI does not prove host-native activation, production integrations, or realized performance improvements. No publication or merge is implied by this release preparation.
