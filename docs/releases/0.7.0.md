# RhapsodIA 0.7.0

## Overview

RhapsodIA 0.7.0 introduces a **lazy shared runtime knowledge layer** for reducing repeated
environment discovery and handoff overhead across collaborating agents. The new
`runtime-harness` expands the catalog from **51 to 52 Agent Skills** while retaining
**seven agent profiles** and existing governance/planning/execution ownership boundaries.

The final 0.7.0 design does not treat the harness as a database that every skill must
understand. Skills continue to declare what they need through their normal workflows;
agents/runtime infrastructure resolve exact capabilities and reuse verified observations.

## Highlights

- Minimal bootstrap with only the already-running Python plus bounded skill/agent catalogs.
- Arbitrary **lazy exact tool discovery**: `ensure tool://docker`, `tool://dotnet`, etc.
- Immutable merged snapshots shared among agents; no direct `current.json` editing.
- Negative-cache reuse for missing tools with TTL + PATH/PATHEXT search fingerprint.
- Explicit `observe-tool` for already-found executables outside PATH.
- Explicit `observe-resource` for stable reusable local files/scripts inside approved roots.
- New `resource://...` references available to lookup, bounded context and handoff pins.
- Global runtime scope no longer churns on PATH or Git HEAD changes.
- Read-only resolver/MCP remains read-only; discovery/publication requires existing writer authority.
- Optional graph projection includes Resource nodes without making graph infrastructure mandatory.
- All seven agent profiles understand the reuse/discover/share contract.
- Package release remains `0.7.0`; Runtime Harness has independent version `1.1.0`.

## Why this changes agent startup

Without shared observations, Agent A may locate Python/.NET and Agent B may later repeat
the same search before finding Docker. With 0.7.0:

```text
Agent A requires python + dotnet
  -> python already known
  -> ensure tool://dotnet
  -> snapshot N+1 published

Agent B requires dotnet + docker
  -> dotnet exact cache hit
  -> ensure tool://docker
  -> snapshot N+2 published

Agent C requires python + docker
  -> two exact cache hits
  -> zero discovery
```

The registry grows only when useful observations are needed. It does not pre-scan a fixed
catalog of tools and does not turn a large environment dump into prompt context.

## Shared knowledge boundary

Agents have autonomy to share **mechanically verifiable runtime knowledge**:

- executable locations and file/stat identity;
- reusable files/scripts inside the workspace or registered skill roots;
- bounded runtime handoff pins.

They do **not** publish arbitrary narrative conclusions, permissions, business/technical
decisions, test success, credentials or conversation history into the environment registry.
Those claims remain governed by the existing domain artifact/handoff/evidence contracts.

This separation keeps shared runtime state useful without creating a second uncontrolled
memory or authority plane.

## Lazy discovery and negative caching

`ensure` accepts only exact `tool://<id>` references. It searches absolute current PATH
directories (and PATHEXT on Windows), never performs a drive-wide scan and never executes
the candidate. Success publishes the observed path; failure publishes a bounded missing
observation.

A missing observation is reused while both its TTL and the hashed PATH/PATHEXT search
space remain unchanged. If the search space changes, only that requested missing tool is
eligible for rediscovery. PATH therefore no longer makes every cached skill/resource
observation stale.

## Reusable resources

`observe-resource resource://<namespace>/<id> --path <FILE>` stores a typed location
relative to the workspace or a registered skill. The observed bytes are hashed at
publication and current bytes are hashed again on resolution/handoff. A changed file can
remain a valid location, but the result reports that the bytes changed and old handoff
pins fail closed.

This is intended for resources agents would otherwise repeatedly locate, such as:

- validators;
- build/test scripts;
- stable local config templates;
- reusable generated-independent helper files.

It is not a general note store.

## Multi-agent publication model

Each discovery/publication creates a new immutable snapshot. The writer takes the short
local lock, reloads the **latest** snapshot, merges its observations and atomically moves
`current.json` after the new snapshot is durable. This prevents sequential agent
observations from overwriting one another and preserves last-good state.

The lock is cooperative and bounded; it is not distributed consensus. Agents never edit
snapshot JSON themselves.

## Handoffs

`runtime-handoff-v1` can pin `resource://` entries in addition to tools, skills, agents,
repository files and workspace identity. Receivers reuse those identities rather than
rediscovering paths. Modified pinned content causes `STALE_HANDOFF`.

Runtime receipts remain transport hints only. They do not replace RhapsodIA agent
handoffs, ecosystem handoff contracts, checkpoint gates, source reads or validation.

## Portability

The executable core requires Python 3.10+ and standard library only. It has no mandatory
OS-specific shell, graph database, MCP service, external orchestrator, cloud API or package
manager. Paths are handled as argv/filesystem values rather than shell strings.

Windows-specific PATHEXT handling and POSIX executable-bit checks are small adapters in
the discovery layer. Optional POSIX and PowerShell bootstrap scripts remain conveniences,
not semantic dependencies.

## Optional MCP and graph integration

The local stdio MCP surface deliberately remains read-only (`status`, `resolve`,
`context`). It does not expose `ensure` or `observe-*`, so connecting MCP cannot silently
turn a reader into a runtime-state writer.

Graph export remains optional and now projects Environment/Tool/Skill/Agent/Resource
membership. It still does not infer permission, dependency, ownership or compatibility
relationships.

## Validation and evidence boundary

The runtime test suite covers lazy discovery, cache reuse, negative cache invalidation,
resource publication, cross-process sharing, handoff change detection, safety guards,
MCP read-only behavior and existing runtime contracts. Repository integration/release
checks validate packaging and agent guidance.

Local byte/timing measurements are not claims about billed-token savings or end-to-end
agent speed. Those require paired native agent runs with frozen correctness/authority
gates and explicit token/tool-call/latency evidence.

## Continuing architecture

RhapsodIA 0.7.0 adds a runtime observation layer beneath the existing skill/agent system:

```text
host/session
  -> minimal runtime bootstrap
  -> exact read-only lookup
  -> lazy bounded discovery only when needed
  -> immutable shared observation
  -> compact handoff/reuse
  -> optional graph projection
```

The goal is to move repeated mechanical discovery out of model reasoning while preserving
portable skills, explicit ownership and evidence-before-completion.
