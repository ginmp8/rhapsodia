# Reproducible HTML and presentation

## Stable mechanics
Use fixed bundled template/CSS/JS, canonical serialized payload, fixed configuration and one-pass safe template substitution. The same material inputs produce identical HTML bytes. Required behavior is not regenerated by an LLM on each render. Input aliases, duplicate IDs, missing endpoints, non-finite values and oversized imports fail before writing.
Built-in layouts use stable ordering and no wall-clock seed. Force is explicitly bounded and never runs forever. A local G6 bundle is a separate versioned input; renderer failures must remain visible.

## Limits
System fonts, browsers, device scale and OS rendering can change pixels even with identical HTML. Test semantic visibility/interactions and bounded visual differences rather than promise pixel identity everywhere. User view state is separate from source identity and changes the display intentionally. Manual positions use stable node IDs, finite bounded coordinates and sorted serialization; coordinates are never inferred as facts. Equal generated HTML still starts with the same automatic layout. Reproducibility does not forbid deliberate user movement.
No remote runtime assets or telemetry are required. The optional local live-query server is user-started and must not be confused with a standalone static snapshot. No persistent user state is silently placed in web storage.

## Gate sequence
Validate input -> render twice/compare bytes -> inspect JS syntax -> run Python regressions -> run available browser interactions/network/error checks -> inspect relevant screenshots -> freeze/package. Preserve old tests; adding a feature cannot silently rewrite old expected outcomes. Missing browser/G6/host capability means not-run for that specific claim, not pass.
