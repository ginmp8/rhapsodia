# Optional local G6 integration

## Offline default
The complete workspace uses a bundled original SVG renderer. It needs no G6, CDN, network, API key or package installation. Default `--backend auto` remains offline.

## Optional reviewed bundle
Supply `--security-profile extended --g6-js /local/g6.min.js --g6-sha256 <EXPECTED_SHA256>` and choose `--backend g6` or auto to inline a reviewed G6 UMD build. A missing/mismatched hash fails before any output replacement. Hashes identify bytes; the operator must separately review provenance and behavior. The integration was authored against the G6 5.1.1 surface. It expects G6.Graph, declarative data, async rendering, behaviors and layout options. Explicit G6 without a supplied file fails; auto can fall back visibly to the builtin renderer.
Extended output is not certified offline even when the bundled template applies a restrictive CSP. The local bundle is executable third-party code: verify its origin, exact hash, license and compatibility separately. Preserve G6 and transitive notices when redistributing it. This package does not include or download that bundle. Do not substitute an arbitrary latest release without browser regression tests.
G6 runtime was not exercised in the delivered validation environment because no verified bundle was available. Builtin renderer browser tests are not G6 compatibility proof. The standalone workspace and all five views do not depend on this optional path.

## Node drag bridge
The optional configuration explicitly enables `drag-element` with no modifier key, no animation and `dropEffect: none`. Read `getNodeData()` after node drag and before redraw/state or image export to mirror changed coordinates into the same presentation-only position overlay as the builtin SVG. There is no canonical graph write. The published G6 drag and data documentation is the API reference; optional G6 runtime remains a separate gate from builtin pointer tests.
