# Compression Playbook

## Priority

1. Preserve the target as a typed procedural contract: activation/interface, authority, workflow/order, tool protocol, scoped rules, safety, evidence, compatibility, outputs, and execution clarity.
2. Preserve rare but operative guards, modalities, negations, precedence, exceptions, trust boundaries, thresholds, and stop conditions before optimizing common prose.
3. Remove duplicated warnings/rationale/filler.
4. Shorten inflated wording and behavior-irrelevant examples.
5. Consolidate repeated rules without collapsing distinct duties.
6. Move branch-specific detail to progressively loaded references only with an explicit load condition.
7. Compress activation/frontmatter only with targeted activation evidence; high expected cost never overrides routing correctness.

Token reduction is rejected when it depends on weaker activation, authority, scope, workflow/tool protocol, safety, validation, evidence/citation, compatibility, output contract, progressive loading, or readability.

## Levels

- `readable`: default for `SKILL.md`, activation, authority, safety, gates, outputs.
- `dense`: low-risk references, reports, examples.
- `max-safe`: only after all preservation/readability gates pass; never a blanket instruction.

## High-yield moves

- Explain a stable rule once and reference it where safe; do not replace a critical guard with an ambiguous pointer.
- Use imperatives/key-values; keep compact matrices only when they clarify distinctions.
- Merge duplicate negatives but retain negatives preventing false activation, unsafe edits, scope drift, fabricated validation, lost citations, or precedence changes.
- Keep only behavior-calibrating examples.
- Shorten `in order to -> to`, `utilize -> use`, `perform validation -> validate` when modality is unchanged.
- If validation fails, repair the smallest broken span and rerun the same gate before broader cleanup.
- Do not hide local growth behind net reduction; justify or revert changed files/sections that grow.

## Placement and loading

Classify required instructions before moving them:

- `entrypoint`: must remain in `SKILL.md` because it controls activation, authority, mutation/stop boundaries, mandatory sequence, or a hard gate needed before any branch load.
- `reference`: may live in a progressively loaded file only when `SKILL.md` states when/why to load it.
- `either`: location is not semantically material, but the chosen path must remain reachable and readable.

Reachability alone is insufficient. A moved rule is preserved only when the agent can determine the required load condition before that rule is needed.

## Critical regions

Do not compress critical regions merely because they look verbose. Demonstrate equivalence for commands, URLs, paths, env vars, schemas, flags, proper nouns, versions, numbers, modalities (`must`, `must not`, `should`, `may` when operative), negations, guards, precedence/exceptions, trust boundaries, safety rules, validation rules, evidence/citation rules, output requirements, and stop conditions.

## Risk labels

- `low`: wording shortened; no semantic duty moved/removed.
- `medium`: duplicates merged or detail moved; refs, load condition, and consumers verified.
- `high`: activation, authority, workflow, scope, safety, validation, compatibility, output, stop, or evidence/citation wording changed.
- `blocking`: equivalence cannot be demonstrated or a hard gate weakens.

High-risk changes require targeted regression evidence; blocking changes are rejected.
