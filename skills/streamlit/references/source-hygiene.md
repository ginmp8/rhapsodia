# Source and License Hygiene

Use this reference when the task depends on current Streamlit behavior, licensing, attribution, or copying risk.

## Source hierarchy

Prefer these sources in order:

1. official Streamlit documentation;
2. official Streamlit GitHub repositories;
3. official release notes or migration notes;
4. user-provided code, logs, or deployment context;
5. community examples only as inspiration, not as source truth.

## Clean-room rule

Do not reproduce third-party skill text or scraped documentation blocks. Summarize behavior in original words. Keep examples small and task-specific.

## Attribution

When bundling or adapting material from an external source, include an attribution note and verify the license. If the source license is absent, unknown, or incompatible, do not copy the material into this skill.

## Current facts

Streamlit APIs can change. For version-sensitive features such as auth, fragments, deprecations, config flags, and deployment behavior, verify current official documentation before giving exact claims.
