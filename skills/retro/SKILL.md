# Retro

## Mission and activation

Review an **observed** engineering/agent work session and propose concrete improvements to its environment, tests, instructions and tooling. This is not an incident postmortem, a generic performance benchmark or an authority to rewrite RhapsodIA controls.

## Workflow

1. Identify the run/session, source revisions and available logs, diffs, test receipts, failures and decisions. If raw logs contain sensitive information, extract only sanitized evidence. Prefer current repository records over narrative recollection.
2. Compare expected workflow with observed behavior. Distinguish missing evidence, confirmed failures, recurring friction and hypothetical opportunities.
3. Examine: repository navigation; deterministic lint/typing/tests and whether CI runs them; unnecessary or misleading instruction files; model/context or tool-call waste; inaccessible but relevant sources; and review-versus-implementation responsibilities.
4. Rank only actionable improvements by severity, causal linkage, recurrence likelihood and cost. Prefer a deterministic guard (test/linter/CI/schema) over an unenforceable prose rule where practical.
5. Separate **recommendations** from authorized changes. Route implementation to **Magia** or **Software Improvement Loop**, technical policy to **Mago**, governance impacts to **Nomia**, and Skill package optimization to **Skill Booster**.
6. For reusable verified findings, propose a sanitized lesson for Local Graph Engine through existing approved memory interfaces; never store credentials, raw logs, unverified causes or change system policy automatically.
7. Report observed evidence, source pointers, improvement hypotheses, minimal acceptance checks, responsible owner and unknowns. Never claim a fix, runtime gain or regression pass without execution.

## Scope protections

Review only the agreed session. Do not auto-edit code, protected evidence, tests, policies, issue labels, or agent instructions; prepare an actionable patch plan or handoff instead. No owner receives additional authority through a retrospective.

## Host portability

Use supplied session logs, diffs and verification results or authorized read-only connectors when a local repository/terminal is unavailable. If primary evidence is insufficient, provide a limited retrospective and list missing inputs, rather than inventing causal observations. Proposing a Graph lesson is not evidence it was stored.
