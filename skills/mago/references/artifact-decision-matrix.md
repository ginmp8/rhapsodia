# Artifact Decision Matrix

Use this matrix after selecting the rigor profile and before creating files. An artifact exists only when its trigger is true or a canonical identity/infrastructure rule requires it. Do not create an optional artifact merely because a template exists.

| Artifact | Creation trigger | Owner | Consumer | Validation rule | Retention rule | Why it cannot be represented safely elsewhere | Minimum profile |
|---|---|---|---|---|---|---|---|
| `cycle.yaml` | a new resolved cycle identity is created | Mago | Mago, Nomia, Magia | identity and repo-board validators | retain for cycle lifetime | cycle identity and immutable metadata are board-level source truth | infrastructure |
| `discovery-state.json` | repository discovery is active or resumable | Mago | Mago discovery | artifact and repo-board validators | retain while discovery remains active; archive with cycle evidence | resumable frontier/state cannot be inferred safely from candidate prose | conditional |
| `discovery-index.yaml` | more than one candidate or discovery checkpoint exists | Mago | Mago discovery/order | artifact and repo-board validators | retain with discovery evidence | deterministic candidate index prevents prose-only ordering drift | conditional |
| `candidates/<candidate>.md` | a repository-backed candidate must be evaluated before registration | Mago | Mago order/define | artifact validator and evidence review | retain when cited by registry/spec; otherwise archive | candidate evidence and rejection rationale need stable provenance | conditional |
| `registry/<spec_id>.yaml` | a spec identity is registered | Mago | all board skills read-only by authority | repo-board, identity, duplicate, dependency validators | immutable identity record retained for board lifetime | registry is canonical source for identity, dependency, and planning state | infrastructure |
| generated `spec-catalog.yaml` | an external catalog projection is requested | generated by Mago script | humans/tools | generated-view reproducibility validator | disposable; regenerate from registry | aggregate view must not be hand-maintained or canonical | external |
| generated `define-queue.yaml` | an external define-order projection is requested | generated by Mago script | humans/tools | generated-view reproducibility validator | disposable; regenerate from registry | ordered view derives from dependency and registry truth | external |
| `manifest.yaml` | a package exists | Mago; narrow Magia state sync only as separately authorized | Mago, Magia | package identity/status validator | retain for package lifetime | package identity and source links require one machine-readable index | quick |
| `prd.md` | behavior, scope, requirements, or acceptance is defined/refined | Mago | Mago, Magia, Nomia read-only | artifact, requirement, and traceability validation | retain and version with package | intended behavior cannot be safely reconstructed from tasks/design alone | quick |
| `tasks.md` | downstream execution work is planned | Mago; Magia may toggle existing checkboxes after truthful completion | Magia | task/dependency/package and traceability validators | retain with execution history | dependency-safe executable decomposition has separate lifecycle from PRD prose | quick |
| `validation.md` | any changed behavior or planning obligation requires proof design | Mago | Magia | package and traceability validators | retain with package; runtime outcomes go to Magia evidence | planned validation must remain distinct from runtime evidence | quick |
| `notes.md` | assumptions, blockers, evidence nuance, or planning rationale cannot fit safely in touched canonical artifacts | Mago | Mago, Magia read-only | artifact/package and boundary review | retain while referenced; consolidate resolved noise during refine | evolving planning context must not pollute normative requirements | standard |
| `technical-design.md` | architecture, data flow, contract, failure, performance, security, migration, observability, rollback, or implementation approach is material | Mago | Magia | technical-design and traceability validators | retain while design is active; supersede explicitly | technical decisions and system interactions need coherent design context | conditional |
| `complexity-reduction-plan.md` | evidence supports simplification, de-abstraction, or behavior-preserving refactor planning | Mago | Magia | artifact/package plus simplification-evidence review | retain through execution/reconciliation; archive after convergence | before/after complexity hypotheses and preserved behavior need focused treatment | conditional |
| `adr.md` or planned ADR set | a material planned technical trade-off needs a durable decision | Mago | Mago, Magia | artifact/static ADR quality and traceability review | retain permanently; supersede, never overwrite history | durable decision status, alternatives, and consequences need independent history | conditional |
| `execution-handoff-plan.md` | execution spans phases, repositories, migrations, contracts, rollout, or special validation sequencing | Mago | Magia | planning-execution handoff validator | retain through reconciliation | bounded execution approach and evidence expectations cannot be reduced to task titles | conditional |
| `contract-spec.md` | a public/internal API, event, schema, file, protocol, or consumer contract changes | Mago | Magia and contract consumers | artifact, traceability, OpenAPI/AsyncAPI or repository contract checks as applicable | retain/version with contract | compatibility obligations need an explicit contract boundary | conditional |
| `migration-strategy.md` | data/schema/configuration migration, backfill, coexistence, or destructive change exists | Mago | Magia, operators | artifact, migration, compatibility, rollback review | retain through completed migration and rollback window | staged migration and reversibility cannot be safely embedded in generic tasks | conditional |
| `observability-design.md` | new/changed behavior needs logs, metrics, traces, dashboards, alerts, or correlation | Mago | Magia, operators | artifact and observability coverage review | retain while signals are operationally relevant | planned signals and failure detection need explicit coverage | conditional |
| `operational-requirements.md` | service operation, SLO/SLA, capacity, resilience, recovery, or support behavior changes | Mago | Magia, operators | artifact and evidence review | retain while requirements apply | operational obligations are normative and must not be hidden in design prose | conditional |
| `security-and-risk-considerations.md` | auth, authorization, secrets, privacy, PII, threat, fraud, compliance, or security posture is affected | Mago | Magia, security/compliance reviewers | artifact, boundary, evidence, and v2 relational security planning review | retain according to package and compliance policy | security assumptions, controls, and residual technical risks require focused auditability | conditional |
| `open-questions.md` | unresolved questions are numerous, cross-artifact, or blocking enough to need a shared queue | Mago | Mago and handoff consumers | artifact and closure review | delete or archive when all entries resolve | a shared unresolved queue prevents silent loss across artifacts | conditional |
| generated `change-delta.md` | an existing spec version is compared or a public delta is imported/exported | generated by Mago workflow | reviewers/adapters | `validate_change_delta.py` plus source-ID review | archive when policy requires; otherwise delete after canonical merge | explicit added/modified/removed/preserved comparison is useful but must not become canonical | external |
| generated SDD adapter files/report | Spec Kit, Kiro, or OpenSpec import/export/round trip is requested | generated by Mago workflow | external tools/reviewers | source validator, target validator, `validate_sdd_adapter_report.py`, loss review | disposable or caller-owned audit attachment | compatibility projection and loss disclosure must remain separate from canonical planning | external |
| generated `planning-reconciliation.md` | current Magia evidence must be compared with Mago intent | generated by read-only Mago reconcile mode | Mago planner, Nomia/Magia handoff consumers | reconciliation contract and evidence-provenance review | caller-owned report; never canonical runtime evidence | convergence classifications compare two authorities without rewriting either | external |

## Profile minimums

For an already registered package:

- `quick`: `manifest.yaml`, `prd.md`, `tasks.md`, and `validation.md` - four package artifacts.
- `standard`: the quick set plus `notes.md` - five package artifacts - and only triggered conditional artifacts.
- `governed`: the standard set plus every conditional artifact whose risk/contract/migration/security/operations/architecture trigger is true. Governed does not create irrelevant files; it requires explicit omission rationale for high-risk trigger families.

The previous full-package path normally required at least manifest, PRD, tasks, notes, validation, and technical planning. The quick minimum is therefore at least two files fewer before triggered artifacts and uses five input groups instead of the former eight individually requested values: resolved identity, bounded scope, known behavior, evidence source, and validation path.
