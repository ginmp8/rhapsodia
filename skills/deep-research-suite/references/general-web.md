# General comparison / best-practice research

## When to load

Use for comparisons, current industry practice, product trends and community experience. Treat vendor statements as claims to verify, and anecdotal experiences as context, not population estimates.

## Evidence procedure

1. Establish time/version/jurisdiction and a comparison matrix with the same dimensions for each option.
2. Find original specifications and changelogs; separate feature availability from roadmap or preview announcements.
3. Search independent benchmark methods, transparent field reports, engineering postmortems, and reproducible repositories. Reddit, Hacker News, Stack Overflow, Dev.to, blog posts, Discord and social media are secondary experience sources; never convert popularity into factual correctness.
4. Compare methodology, conflicts of interest, sample size and environment before aggregating comparisons. Evidence copied across sites is still one source.
5. Record exact values only with attributable sources and dates. In the absence of sound quantitative comparison, use a qualitative statement with uncertainty.
6. Prefer the recommendation supported by the user's stated criteria, with the failure conditions that would change it.
